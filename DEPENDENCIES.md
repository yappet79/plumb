# Plumb — dependency matrix

> Purpose, borrowed word for word from the dependency matrix this one is modelled on: **"so we
> don't break what already works."** What depends on what, what a change touches, and where
> changing is dangerous.
>
> Generated by reading the code, not from memory. Re-read the code before trusting this file.

---

## The unusual shape of this module

**No script imports another script.** Every one of the nine is standalone: `node fs`, `node
path`, `node child_process`, nothing else. There is no `lib/`, no shared module, no
`package.json` dependency that must be installed.

That is deliberate and it buys something real — anyone can clone this and run any single script
with no install step, and a broken script cannot take another one down. It is the reason
`check-layout.mjs` works in a repository that has never seen `npm`.

**And it is the module's single largest risk.** With no shared module, shared behaviour is
shared by copy. Three files launch Chrome; two resolve API keys; two carry the same security
flags. Fix one, and the other two keep the bug — silently, because nothing links them.

**This already happened, twice, in one day.** Both entries below are real.

## Level 0 — documents that govern behaviour

Nothing executes these, so they are easy to forget when changing code. Every one of them is a
contract the scripts are expected to honour.

| File | What it decides | Read by | Risk of change |
|---|---|---|---|
| `SKILL.md` | routing (`description`), onboarding, the whole process | Claude, on invocation | **CRITICAL** — the `description` line is the ONLY thing that decides whether Plumb is invoked at all. Break it and the module simply never fires |
| `tokens.md` | palette, semantic colour, ground, pills | brief authoring | HIGH — changes every artefact drawn afterwards |
| `typography.md` | type floors per artefact type | brief authoring | HIGH — floors are what `--min-font` enforces; the two must agree |
| `posters.md` | poster genre: tiers, canvas, icons | brief authoring | MEDIUM — one medium only |
| `references.md`, `fonts.md` | archetypes and font pairings | brief authoring | LOW |
| `themes.json` | six palettes with computed contrast | `theme.mjs` | MEDIUM — the only doc a script actually parses |
| `templates/*.html` | the quality floor, passed as `--ref` | `bakeoff.mjs` | LOW to change, HIGH to delete |

**The trap here:** `typography.md` says the poster content floor is 26px; `check-layout.mjs
--min-font` takes the number on the command line. Nothing ties them together. Change the doc and
every future run uses the new number; change nothing and an old habit keeps passing `18`. **If
you change a floor in a doc, grep for the old number in the briefs and in this file.**

## Level 2 — file transformers, no network

| Script | Lines | Reads | Writes | Risk |
|---|---|---|---|---|
| `embed-fonts.mjs` | 85 | Google Fonts once, then inlines | the same HTML | LOW |
| `fill-slots.mjs` | 85 | a photo directory | the same HTML | LOW |
| `fit-deck.mjs` | 65 | — | the same HTML | LOW |
| `theme.mjs` | 104 | `themes.json` | stdout | LOW |
| `pptx-check.mjs` | 100 | a `.pptx` (a zip) | stdout, plus a temp dir it creates and removes | **MEDIUM** — it does not write the deck, but it does `mkdirSync`, `rmSync`, and shells out to unpack |

**That last row used to say "LOW — read-only, never writes the deck", and that was wrong.** A
security pass caught it: the script creates and deletes a directory and starts a child process.
The rating came from what the script is *for*, not from what it *does* — the easiest kind of
mistake to make in a document like this one, and the reason the header says to re-read the code
before trusting the file.

**All five edit files in place.** None of them keeps a backup. That is fine for a generated
artefact and dangerous for a hand-edited one — `embed-fonts.mjs` turned a 23 KB template into
720 KB and there was no way back except regenerating.

## Copied behaviour — the actual danger list

| What is copied | Copies live in | What happens when you fix one |
|---|---|---|
| **Chrome launch + `--window-size`** | `bakeoff.mjs`, `check-layout.mjs`, `render-png.mjs` | the other two keep the old behaviour. **This is not hypothetical — see below** |
| `chromePath()` — where Chrome is | the same three | a new install path found by one is invisible to the others |
| Security flags: `--host-resolver-rules` blackhole, throwaway `--user-data-dir` | `bakeoff.mjs`, `render-png.mjs` | `check-layout.mjs` has the profile but **not** the resolver blackhole. It injects a probe into a page written by a model and lets it run. Worth closing |
| `resolveKey()` — key from env, else Supabase | `bakeoff.mjs`, `image.mjs` | a change to key handling has to be made twice, in the two files that touch money |
| The `.local-keys.mjs` optional import | the same two | — |

### Worked example 1 — the viewport clamp, found the hard way

Chrome refuses to lay out a CSS viewport narrower than ~504px and says nothing about it.

- **03 Aug, morning.** `check-layout.mjs` was reporting every landing page broken at 390px. An
  empty document failed the same way. Root cause found, fixed there: clamp, announce it, measure
  against the width the page actually got.
- **03 Aug, evening.** The same bug was still live in `render-png.mjs`, because the Chrome launch
  is copied, not shared. Worse there: Chrome laid the page out at 500px and then **scaled the
  result down** into the 390px image that was asked for. The file came out the right size with
  the wrong layout inside it — media queries had fired at 500. Proved with a 390px ruler box that
  stopped short of the frame edge while the page reported `clientWidth=500`.
- `bakeoff.mjs` renders its contact sheets at 1200–1600px, so it never hit the clamp. **It is
  still unfixed and will bite the first person who runs a bake-off at phone width.**

### Worked example 2 — the rule that only checked one axis

`busts-card` was written to catch a table column pushed out of the right edge of its card. Two
hours later a poster dropped a caption out of the **bottom** of a card onto the cards below —
visible instantly, invisible to the rule. Same class of defect, different axis.

**The lesson both examples teach:** a rule or a fix written for the case in front of you covers
that case. Ask what the *class* is before you write it down.

## Change → what to check

```
Change the `description` in SKILL.md?
  → the module may stop being invoked at all. Test with a fresh session and a plain sentence.
  → the multilingual trigger list is routing, not prose. Do not "tidy" it.

Change a Chrome flag or the window size in ANY script?
  → grep --window-size and chromePath across all three. Decide for all three, not one.

Change a type floor in typography.md or posters.md?
  → grep the old number in briefs and in --min-font habits. The doc does not enforce itself.

Change a rule in check-layout.mjs?
  → re-run it over templates/ AND over the last few artefacts in ~/Downloads.
    Every current exemption exists because a rule fired on something that was fine.
    A new rule that reports nothing new is unproven; one that reports on a clean file is worse.

Change resolveKey or key handling?
  → two files spend money: bakeoff.mjs and image.mjs. Both, or neither.

Change themes.json?
  → theme.mjs parses it. Contrast is computed, not stored — a bad pair fails loudly, which is
    the intended behaviour.

Delete anything in templates/?
  → it is referenced by name in templates/README.md and in SKILL.md Step 0.4.

Rename the skill folder?
  → the install path appears in README.md and SKILL.md. And `.memory/` does not travel: a
    renamed module has amnesia.
```

## Closed on 03 Aug — both of the above

**`scripts/lib/chrome.mjs`** now owns `chromePath()`, the launch flags, the viewport clamp and
the file:// helper. The three copies are gone. They had already drifted apart: one knew about
`CHROME_PATH` and chromium, the other two knew about Edge — so on Linux with only chromium
installed, checking worked and rendering did not. Nobody would have found that by reading.

The "clone and run one script" property survives: it is a relative import inside the repo, not a
package. `node scripts/check-layout.mjs page.html` still works on a fresh clone with no install.

**`fixtures/` + `scripts/selftest.mjs`** — one page per rule, each the smallest thing that
triggers exactly that rule, plus a control that must stay clean.

```bash
node scripts/selftest.mjs     # 0 all pass · 1 a regression · 2 could not run
```

Its first run paid for itself three times over:

- **`covered` did not exist.** A fixture with a card painted over a paragraph — plainly visible —
  passed every rule, because rule 2 compares text against text and the covering panel had no text
  of its own. Now hit-tested with `elementFromPoint` rather than guessed from geometry.
- **The probe ran at parse time.** It serialised its report before `load`, so any exception thrown
  from a load handler was invisible, and every measurement was taken before the page had settled.
  It now runs a beat after load — with a timer, not `requestAnimationFrame`, which never fires
  under `--virtual-time-budget`.
- **The single-line exemption was measured on `clientHeight`**, which includes padding, so a
  one-line table cell with 12px of padding stopped counting as one line and got reported as lost
  content. Now measured on the content box.

## Closed on 03 Aug — from the security pass

Two findings, both confirmed by three independent reviewers each, both fixed and both proved by
running the old code and the new one against the same input rather than by argument.

**Command injection through a `.pptx` filename** (`pptx-check.mjs`). The paths were interpolated
into a PowerShell `-Command` string. `execFileSync` with an argv array protects the argv
boundary and nothing else — argv[2] there is a script that PowerShell parses, so the filename
became executable. Legal Windows filename characters are enough; the only filter was the `.pptx`
extension, which a payload satisfies. Since the tool exists to read a deck somebody else sent
you, the sender chooses that name.
Fixed by passing the paths through the environment, where nothing parses them. **Proved:** the
same payload-named deck created a marker file under the old code and did not under the new one.

**The page under test could write the checker's verdict** (`check-layout.mjs`). The report came
back through a fixed, guessable element id; extraction took the first match while the genuine
report was appended last, so a page carrying its own `<script id="__layout_report">` won. And
`report.measuredWidth || 0` under `if (got && …)` meant omitting the field *skipped* the width
gate instead of failing it.
Fixed with a per-run nonce in the id, removal of anything already wearing it, last-match
extraction, and a required-field check. **Proved:** the same fixture returned
`✅ layout clean · containers: 9` under the old extraction — nine being a number the *page*
supplied — and reports the real overflow under the new one.

Both now have fixtures in `fixtures/`, so a future edit that reopens either one fails the suite.

**The renderer sandbox is back on.** `--no-sandbox` sat in the shared launch args unconditionally
and nothing here needs it — no root, no container. It is now behind `PLUMB_NO_SANDBOX=1`, which
prints a warning when used.

**The checker's temp file moved into a private directory.** It was
`os.tmpdir()/layout-check-<pid>.html`: world-writable location, guessable name, and
`writeFileSync` follows symlinks. `render-png.mjs` already used `mkdtempSync`; this is the same
copy-drift the matrix exists to catch.

**And one finding did not survive measurement.** The review argued that the resolver blackhole
covers hostnames only, so a page could reach `127.0.0.1` or the local network by literal
address. The argument was sound and the conclusion was wrong: tested against a real local
listener, with a control run proving the test could see the channel at all, unrestricted Chrome
reached the server and the existing rule blocked it. Chrome routes IP literals through the host
resolver too. A proxy layer added on that argument was removed again.

Two lessons worth keeping, since both cost real time here:

- **A test whose halves disagree is measuring nothing.** The first version of that test reported
  "0 server hits" while the page reported "fetch OK". The second used `execFileSync`, which
  blocks Node's event loop, so the listener was asleep and every result read as "blocked". Only
  the third — async, with a self-check and a control — said anything true.
- **A finding from a careful reviewer is a hypothesis, not a fact.** Three lenses and two
  vendors are worth a great deal; they are still not worth as much as a listener on a port.

## What is still absent

- **No CI.** `selftest.mjs` exists and nothing runs it automatically.
- **No versioning.** No changelog, no version number — a forker cannot tell which set of rules
  they have.
- **No test for the money paths.** `bakeoff.mjs` and `image.mjs` call paid APIs, so nothing
  exercises them; both were changed today and only syntax-checked.

Listed rather than hidden, because a matrix that only shows what exists is half a map.
